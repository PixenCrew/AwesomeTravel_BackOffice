## 2. 보안 (Security)

### 2.1 심각·우선 조치

| 항목 | 위치 | 내용 | 권장 |
|------|------|------|------|
| **관리자 테스트 가입 노출** | `MainController.java` | `POST /admin` 으로 누구나 Admin 생성 후 로그인 가능. `adminService.createUser(admin)` 호출. | **운영 환경에서는 제거 또는 비활성화.** 개발 전용이면 프로파일/플래그로 분리. |
| **역할 기반 경로 미적용** | `SecurityConfig.java` | `.requestMatchers("/admin/**").hasRole("ADMIN")` 가 **주석 처리** 되어 있음. | `/admin/**` 및 `/api/admin/**` 는 ADMIN 역할 필수로 적용 권장. |
| **CSRF 비활성화** | `SecurityConfig.java` | `csrf.disable()` 로 전체 비활성화. | 운영 시 CSRF 활성화 검토 (폼/API 구분 후 적용). |

### 2.2 메서드 단위 권한

- `@PreAuthorize("hasRole('ADMIN')")` 적용된 곳: **FileController** (`/api/files`), **InquiryAdminController** (`/api/admin/inquiry`) 만 확인됨.
- 나머지 admin API·화면(상품, 투어, 항공, 환불, 공지, FAQ, 리뷰, 구매관리 등)은 **authenticated 만 필요**, 역할 검사 없음.
- **권장:** 환불 승인·구매 상태 변경·회원 정보 등 중요 기능은 ADMIN(또는 SERVICE) 역할 제한 적용 검토.

### 2.3 인증 백엔드

- `AdminService` 가 `UserDetailsService` 구현, **admin** DB 테이블 사용 (JDBC).
- 로그인 페이지 `/login`, 처리 URL `/login`, 성공 시 `/` 이동, 로그아웃 시 세션·JSESSIONID 제거. 구성은 적절함.

## 3. 버그·예외 처리 (Bugs)

### 3.1 Optional.get() 사용 (NoSuchElementException 위험)

| 파일 | 라인 부근 | 내용 | 권장 |
|------|------------|------|------|
| **TourController** | 227 | `tourRepo.findById(id).get()` | `.orElseThrow(() -> new IllegalArgumentException("투어를 찾을 수 없습니다."))` 등 처리. |
| **TourController** | 513 | `hotelRepo.findById(location.getHotel().getId()).get()` | 동일. null/미존재 시 예외 또는 분기 처리. |
| **ProductController** | 134 | `tourRepo.findById(product.getTour().getId()).get()` | 동일. |
| **ProductController** | 335 | `productAdminRepo.findById(id).get()` | 동일. |
| **AirController** | 276 | `airRepo.findById(id).get()` (복제용) | 동일. |
| **MenuCodeController** | 106 | `menuCodeRepository.findByCode2(id).get()` | 동일. |
| **BannerController** | 109, 134 | `banner.get()` | 이미 `banner.isEmpty()` 체크 후 호출이면 안전. isEmpty() 없는 다른 Optional.get() 있으면 검토. |
| **CountryCodeController** | 106, 131 | `countryCode.get()` | Optional 반환 후 isPresent/isEmpty 확인 여부 확인 후, 없으면 추가. |
| **CityCodeController** | 132, 169 | `cityCode.get()`, `Objects.requireNonNull(cityCode.get())` | requireNonNull 은 null 시 NPE. Optional 이면 orElseThrow 권장. |
| **AirportController** | 114, 138 | `airport.get()` | isEmpty 체크 여부 확인 후 미체크 시 수정. |
| **AirlineController** | 86, 111 | `airline.get()` | 동일. |
| **ProductServiceCommon** (common) | 461 | `purchaseProductRepo.findById(id).get()` (cancelPurchase) | ID 없을 때 예외. `.orElseThrow(() -> new IllegalArgumentException("구매 내역을 찾을 수 없습니다."))` 권장. |

### 3.2 기타

- **RefundService**: `requestRefund`, `approveRefund`, `processRefund` 등은 `orElseThrow` 사용. `processRefund` 에서 패키지 환불 시 `productServiceCommon.cancelPurchase(refund.getPurchaseId())` 호출 — BackOffice 공통 모듈의 `cancelPurchase(Long)` 내부에서 `findById(id).get()` 사용 시, 잘못된 ID면 예외 발생. 위 3.1 반영 시 함께 해소.
- **날짜 파싱**: NoticeViewController 등에서 `startAt`, `endAt` 파싱 실패 시 `System.err` 만 출력하고 있을 수 있음. 사용자/관리자에게 에러 메시지 전달 및 로깅 정리 권장.

## 4. 설계·일관성 (Design)

### 4.1 로깅 — **적용 완료**

- **적용 내용:** Slf4j Logger 로 통일. System.out/System.err 제거 후 `log.debug`, `log.info`, `log.warn` 등으로 교체. API 키·URI 등 민감 정보는 로그에 남기지 않음.
- **수정된 클래스:** MainController, RefundService, RefundViewController, FileUploadService, PurchaseProductService, PurchaseAirService, NoticeViewController, FaqService, ExcelService, CommonCodeService, OpenApiService, RandomGenerator, AdminService. (ProductServiceCommon 예약대기 관련은 기존 Logger 사용.)
- **권장:** 운영에서는 debug 레벨 비활성화.

### 4.2 API·뷰 중복

- **공지**: `NoticeViewController` (폼 기반 `/notice`) + `NoticeController` (REST `/api/admin/notices`) 동시 존재. 유지보수 시 두 경로 모두 고려 필요.
- **환불**: `RefundViewController` (`/refund`) + `RefundAdminController` (`/api/admin/refunds`) + `RefundController` (`/api/refunds`). `/api/refunds` 는 클라이언트용일 수 있음 — 역할·권한 명확히 할 것.

### 4.3 공통 모듈 (renewal.common)

- **ProductServiceCommon**, **AirServiceCommon** 등은 클라이언트·백오피스에서 공유. BackOffice 전용 수정 시 클라이언트 영향 검토 필요.
- **cancelPurchase(Long)** 등 공통 메서드 내부의 `.get()` 제거는 공통 모듈 한 곳만 수정하면 양쪽에 반영됨.
